## jobboard v0.9.0

### New features

#### Waiting on a pool wakes on every worker that ends
- **What it is:** `jobrun wait --any POOL` now returns as soon as any single worker or monitor of the pool ends,
  also when it succeeds. Before, only a failing worker or the end of the whole pool woke it.
- **How to use it:** nothing changes in the command. A worker that ended prints its own line, e.g.
  `261124-ef4d  done  slurm eris  worker of pool tune queue (261124-5ad8)  after 2h41m`.
- The `still active:` line shows how many workers a pool still runs, e.g. `261124-5ad8 (1 workers)`.

#### Wait again without missing anything
- **What it is:** when jobs are still active, `jobrun wait --any` ends with a ready-made command to wait again:
  `rearm: jobrun wait --any 261124-5ad8 --since 1795600686.518`. Run it as printed: it also reports what ended,
  warned or was removed while you were acting on the first result, which a fresh `wait --any` treats as old.
- **How to use it:** copy the `rearm:` line, or pass `--since TIME` (Unix time) yourself.
- An end in the few seconds of the check that found the triggers may be reported twice; none is lost.

#### Removal log
- **What it is:** every job removed with `jobrun rm`, `jobrun clean`, the trash icon, "Clear finished jobs" or
  `auto_clean_days` is recorded in `~/.jobs/removed.log` (one JSON line: job, status, end time, the command and
  the program that called it). A job missing from the list can now be traced.

### Changed
- On a Slurm node, the CPU and RAM rows show what is **reserved** first, e.g. `16 / 36 cores reserved · 12 used`,
  and the bar fills with the larger of reserved and used: a reserved core is not free for a new job, whatever the
  load says. `jobrun res` shows the same order.

### Fixed
- A Slurm node could show `0 / 36 cores` while your jobs on it were busy, because slurmd's load average and free
  memory lag and can read near zero. A node now shows at least what your jobs on it use, marked `(your jobs)`.
- Removing a finished job could hide its end from someone waiting for it. `jobrun wait --any` now reports it as
  `removed from the registry` with the status it had, also for a pool's workers.
- A job started with `--after X` was cancelled when `X` was removed before it noticed that `X` had finished. It now
  starts if `X` had ended `done`.
