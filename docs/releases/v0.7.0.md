## jobboard v0.7.0

### New features

#### Pools
- **What it is:** a single job whose list of items is worked through by several workers at once. The workers can
  be local processes, Slurm jobs, or both.
- **How to use it:** create a pool with `jobrun pool NAME`, then start each worker with `--pool NAME`. To move a
  job that is already running into a pool, use `jobrun edit ID --pool NAME`.
- **Progress:** the pool has one progress bar for the whole list. It comes from any member printing
  `JOBRUN_PROGRESS`, or from workers printing `JOBRUN_ITEM` once per finished item. A member that only reports
  progress joins with `--role monitor`.
- **When something fails:** a failed worker only raises a warning, and the others keep going. If all workers
  finish but items are left, you also get a warning, so you can check before the next step.
- **Commands:** `--after`, `stop` and `wait` act on the whole pool.
- **Display:** the pool is one row, with its workers listed underneath. Workers show a gear icon and monitors an
  eye icon.

#### `wait --any` and problem reports
- `jobrun wait --any` returns as soon as one job ends, reports a problem or stalls.
- A job can report a problem while it keeps running by printing `JOBRUN_EVENT error|warn <message>`. The job is
  then marked on the board, and you get a notification.

### Changed
- Fewer false "stalled" alarms. The rule now also accounts for jobs whose steps arrive in bursts.
- Notifications are now on by default for finished jobs and reported problems.
- The agent skill explains when to use a group, a chain (`--after`) or a pool.

### Fixed
- The time since the last step could briefly show as negative.
